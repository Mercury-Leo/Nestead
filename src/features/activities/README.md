# activities
Things the family does together outside the kitchen. One page so far: Shows (`/shows`), the family's list of movies and series, added from OMDb.

## How it works
- OMDb's details are saved as a row when a show is added; the page reads rows through `useCollectionState(store.shows)`. Filters, sort and the name search run on those rows (`../../domain/shows.ts`), so opening the page or a card never calls OMDb.
- OMDb is called in three places only: Search in the add sheet (when the form is sent, never per keystroke), choosing a result (its details, short plot), and Refresh from OMDb on one card (`AddShow.tsx`, `actions.ts`). There is no refresh of the whole list, and nothing in the background.
- A result already on the list is marked "In your list"; choosing it, or saving one another device added a moment ago, opens the existing card instead of adding a second (`addShow()`; Supabase's unique constraint turns the second insert away). Opening a card clears filters that hide it, scrolls it into view, opens it, focuses its title and flashes it once (`reveal()` in `Shows.tsx`, `revealed` in `ShowCard.tsx`).
- Length is `runtimeMin`, OMDb's `Runtime`: a movie's running time, or one episode's for a series, shown beside its seasons (`Facts` in `ShowCard.tsx`).
- The status badge at the top of a card is also its control: a press cycles To watch, Watching, Watched; Watched stamps `watchedAt` and leaving it clears it (`statusPatch()`). The badge is drawn at the app's badge size inside a 44px target (`.statusHit`).
- Dropped is the fourth status, for a show the family decided not to watch. It is set on purpose with Drop it in the card's details (`dropShow()`), never by cycling past Watched. A dropped show's badge is muted, and its details offer Restore in Drop it's place (`restoreShow()`); either Restore or a press on the badge brings it back as To watch (`nextStatus()`). All, and its count, leave dropped shows out: they wait under the Dropped filter. Bringing a dropped show into view after Add show switches to that filter, since clearing the filters would not show it (`reveal()` in `Shows.tsx`).
- The star on a poster's top start corner (top left; top right in Hebrew) marks a family favourite, one they would watch again. It is a toggle for the whole family (`aria-pressed`, labelled with the title), apart from the status: starring never changes the status, and a status change, a drop or a refresh never changes the star (`toggleFavorite()`). The sort Favourites first lists starred shows first, each group newest added first (`sortShows()` in `../../domain/shows.ts`).
- Refresh writes `refreshPatch()`: OMDb's fields and `fetchedAt`, never `status`, `watchedAt`, the star or who added it. A field OMDb no longer has is cleared. If OMDb fails, the card says so quietly and nothing is written. The server lets the browser keep an answer for ten minutes; a refresh asks with `cache: 'no-store'` (`lookupShow(id, true)`), so it never saves a cached copy under a new `fetchedAt`.
- Posters are OMDb's `posterUrl` (Amazon's image servers), loaded and cached by the browser with no referrer. Nothing downloads, uploads or stores an image. An Amazon poster link, `…/images/M/<id>._V1_<options>.jpg` (OMDb links a 380 px crop, `._V1_QL75_UX380_CR0,0,380,562_.jpg`, about 40 KB; older rows may hold `._V1_SX300.jpg`), gets a `srcset` of Amazon's `<id>._V1_QL75_SX100/200/300.jpg`, so a card (84–96 px wide) and a search result (44 px) fetch the size they draw: 139 KB instead of 361 KB for a phone's first nine posters. If that version fails, the poster tries OMDb's own link, then shows the placeholder (`Poster.tsx`).
- A long list is built a page at a time: the first 60 of the filtered, sorted list (`SHOWS_PAGE`, `shownCount()` in `../../domain/shows.ts`), then Show more for the next 60, which moves focus to the first new card. A count under the list ("Showing 120 of 300", a polite live region) shows only when there is more than one page. Any change of search, filter or sort, back to an earlier one too, starts from one page. A show brought into view after Add show is built wherever it sorts (`Paging.reveal` in `Shows.tsx`). The list follows the name search through `useDeferredValue`, so the field paints before the cards are built.
- Long lists stay quick (measured in `../../../docs/PERFORMANCE.md#shows-2026-10-04-branch-activitiesshows`): a card builds its details panel only while open; cards are memoised on their fields, so a status change or a keystroke re-renders only the cards it touches; and cards out of view skip layout and paint (`content-visibility: auto`), each counted as its poster's height until laid out.
- The status and kind filters and the sort are a per-family device preference, `showsView` (`readPreference`/`writePreference`); the name search is not kept.
- The Shows collection is not read at sign-in (`preloadStore()` leaves it out); the page shows Loading until its first read.

## Rules & gotchas
- Never call OMDb to show the list or a card, and never refresh more than the one show someone asked for: the free key allows 1,000 requests a day for the whole app (`../../../server/shows/README.md`).
- Save only `posterUrl`, never the image, and never an `img.omdbapi.com` link (it needs the key). `Poster.tsx` also refuses anything but https.
- OMDb text is data. Titles and plots render as React text; in a `<Trans>` string a title goes in a named slot (`<item/>` with `<bdi>`), never as a value (`shows.card.deleteQuestion`).
- Writes go through `shows/actions.ts`, and which fields a refresh may write is decided in `../../domain/shows.ts` (`REFRESHED_FIELDS`), not in a screen.
- Stored statuses are kebab-case (`to-watch`); translation keys are camelCase (`shows.status.toWatch`), mapped by `STATUS_KEY` in `labels.ts`.
- Shows UI stays in this folder; it imports nothing from `../larder/`.
- `ShowCard`'s memo compares `show` field by field (`sameShow()`), because a re-read returns every row as a new object. A new prop for the card must join that comparison, or the card ignores changes to it.
- `contain-intrinsic-size` in `ShowCard.module.css` is the closed card's content height, padding and border excluded: the poster's height at 84 px wide (126 px) and at 96 px on desktop (144 px). If the poster or the card's padding changes, change it too, or the scrollbar jumps as cards appear.
- The star follows the title and the status badge in the DOM, so someone moving by headings meets it after the show's name; CSS places it over the poster against the card (`.starHit`), from the card's 12px padding. If that padding or the poster's corner moves, change its offsets too. Read the field as `favorite === true` and unstar by writing `false` (`../../data/README.md`).
- The details panel is built only while open, so closing a card resets a pending delete question and a refresh message.
- Paging state is keyed to the search, filters and sort (`keyOf()` in `Shows.tsx`) and reset during render when the key changes; the key uses the search as typed, while the list uses the deferred one, so a reveal set in the same event survives. The browser's find-in-page only finds cards already built: past the first 60, people use the name search or Show more.
- After Show more, focus moves to the first new card's title, found by its position in the grid (`grid.current.children[n]`): keep one card per child there.
- `Poster`'s `sizes` must match the width the CSS draws it at (`ShowCard.module.css`, `AddShow.module.css`), or the browser fetches the wrong size.
